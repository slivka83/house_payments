# Начисления по платёжкам

Начисления по месяцам с разбивкой по услугам из платёжек (ЕПД МосОблЕИРЦ и платёжные документы других поставщиков): **веб-страница с графиком** или таблица/CSV/JSON в консоли.

Приложение полностью локальное: **никуда не ходит и ничего не скачивает**. Вы сами создаёте папку поставщика и кладёте туда PDF — приложение читает их и строит отчёты.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Нужен только `pypdf` — им читаются PDF.

## Куда класть платёжки

Все платёжные документы лежат в одном корне (`PAYMENTS_RECEIPTS_DIR`, по умолчанию `data/receipts`), у каждого поставщика — своя папка:

```text
data/receipts/
├── mosobleirc/               # поставщик — это просто имя папки
│   └── 2026-08.pdf
├── mosenergosbyt/
│   └── 2026-08.pdf
└── tko-operator/
    ├── 2026-07.pdf
    └── 2026-08.pdf
```

- Имя папки показывается в интерфейсе как название поставщика (для папки `mosobleirc` — «МосОблЕИРЦ»).
- Вложенность внутри папки любая, имя папки поставщика может быть любым.
- В имени файла должен быть месяц `ГГГГ-ММ` — он используется, если месяц не удалось определить по тексту платёжки.
- Если за один месяц у поставщика несколько PDF, суммы складываются (приложение покажет предупреждение).
- Само содержимое квитанций в гит не попадает: отслеживаются только папки — пустыми файлами `.gitkeep` (см. `.gitignore`). Создавая папку нового поставщика, добавьте в неё `.gitkeep`, чтобы структура зафиксировалась в репозитории.
- Проверить, что нашлось: `python -m payments suppliers`.

## Настройка через env

Все параметры необязательные. Можно положить их в `.env` рядом с проектом (подхватится автоматически) — обычный формат `КЛЮЧ=значение`, ключи из таблицы ниже.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PAYMENTS_RECEIPTS_DIR` | `data/receipts` | корневой каталог с папками поставщиков |
| `PAYMENTS_DB` | `data/payments.sqlite` | одна БД SQLite с кэшем разбора PDF |
| `PAYMENTS_MONTHS` | `12` | сколько месяцев показывать |
| `PAYMENTS_END_MONTH` | последний месяц в папках | последний месяц отчёта, `YYYY-MM` |
| `PAYMENTS_VALUE` | `charged` | показатель: `charged` (начислено, ₽) или `volume` (объём, ед.) |
| `PAYMENTS_HOST` | `0.0.0.0` | адрес веб-сервера |
| `PAYMENTS_PORT` | `8765` | порт веб-сервера |

## Веб-страница с графиком

```bash
python -m payments web
# в консоли появятся адреса, например:
#   http://localhost:8765/      — из браузера Windows
#   http://172.x.x.x:8765/      — IP WSL-машины, если localhost не открывается
```

Если страница не открывается из Windows: сервер слушает `0.0.0.0`, попробуйте `http://localhost:8765/`, затем IP из вывода команды (`ip -4 addr show eth0` в WSL). Порт занят — задайте `PAYMENTS_PORT=8766`.

Сервер запускается один раз: при изменениях кода или `.env` он перезапускается автоматически (в течение секунды), вам достаточно обновить страницу в браузере. Отключить автоперезапуск: `PAYMENTS_RELOAD=0`.

- Диаграмма занимает всю ширину и высоту экрана (кроме шапки с выбором показателя и периода), легенда — справа одним столбцом; период выбирается из 6, 12, 18, 24, 30 или 36 месяцев; первый пункт легенды соответствует верхнему сегменту столбца, и в этом же порядке услуги идут в таблице под диаграммой, с разбивкой по разделам («Жилищные услуги», «Общедомовые нужды (КР на СОИ)», «Коммунальные услуги», «Иные услуги»). Раздел услуги определяется по её названию, а не по вёрстке конкретной платёжки, поэтому одна и та же услуга у разных поставщиков попадает в один раздел. Клик по услуге включает/выключает её на графике, наведение — подсвечивает, кнопка «Скрыть все»/«Показать все» переключает все услуги сразу; у каждой услуги и группы в легенде есть иконка «?» с пояснением, в том числе с названием поставщика; общая сумма над столбцом пересчитывается по видимым услугам;
- над каждым столбцом — итоговая сумма за месяц, при наведении — подсказка по конкретной услуге (у услуг не основного поставщика — с его названием);
- клик по сегменту графика открывает PDF платёжки того поставщика, из которой взята эта цифра (в режиме «Объём» — квитанцию выбранной услуги); если одна и та же услуга есть сразу у нескольких поставщиков, открывается квитанция за месяц (первая найденная); клик по месяцу в таблице работает так же;
- кнопка с иконкой обновления (⟳) пересканирует папки и **разбирает новые/изменённые PDF в БД**. Обычная перезагрузка страницы ничего не разбирает — показывает только то, что уже есть в БД (поэтому первый раз после добавления платёжек нужно нажать ⟳).

Кэши (поэтому переключение периода почти мгновенное):

- разбор PDF — в одной БД SQLite `data/payments.sqlite` (пополняется по кнопке ⟳);
- агрегат по запросу (месяцы + показатель) — в памяти сервера;
- ответы `/api/data` — в браузере, чтобы переключение туда-обратно не ходило на сервер.

При нажатии ⟳ приложение сверяет каждый PDF с БД (`mtime` и размер): изменённые и новые разбираются, разборы удалённых PDF убираются. Удалить БД тоже безопасно — после ⟳ все PDF разберутся заново.

При запуске сервера и при обычной загрузке страницы не происходит ничего, кроме чтения БД: папки не сканируются, PDF не разбираются. Единственное исключение — команды `months`/`suppliers` в консоли: они выполняют действие сразу. Старые сайдкары `{месяц}.json` рядом с PDF игнорируются (источник истины — PDF).

## Консольные команды

```bash
python -m payments web                          # веб-страница с графиком
python -m payments months                       # таблица: категории × месяцы
python -m payments months --format csv --out charges.csv
python -m payments months --format json
python -m payments suppliers                    # папки поставщиков и что в них найдено
```

Параметры команд дублируют env (`--months`, `--value`, `--end-month`, `--receipts-dir`, `--db`, …) и переопределяют их.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют разбор всех трёх форматов, группировку услуг, кэш в SQLite, дедупликацию сводных квитанций, выдачу веб-слоя и страницу (периоды 6–36 месяцев, отсутствие бренда, клик по сегменту открывает квитанцию поставщика). Для запуска нужны PDF-квитанции в `data/receipts/` (они не коммитятся) и `pypdf`.

## Как читаются данные

Формат платёжки определяется автоматически, поддерживаются три:

- **ЕПД МосОблЕИРЦ** («Единый платёжный документ» / «Расчёт размера платы за жилищно-коммунальные и иные услуги»): берутся только «объём услуг» (в единице измерения услуги) и «Начислено по тарифу» (деньги). Колонки «Перерасчёты», «Задолженность/Переплата», «Оплачено» и «ИТОГО» игнорируются, строки с нулевым начислением не попадают в отчёт. Разделы «Начисления за жилищные/коммунальные/иные услуги» используются как основа для группировки.
- **Квитанция УК** («Жилищно-коммунальные и иные услуги», таблица «Расчёт размера платы за жилое помещение…»): из каждой услуги берутся объём (в единице — Гк, м³ и т.п.), тариф и колонка «Начислено», а «Задолженность/Переплата» и «Оплачено» игнорируются. Строки из справочной информации (показания счётчиков) начислениями не считаются.
- **Счёт АО «Мосэнергосбыт»** (`СЧЁТ ЗА ЭЛЕКТРОЭНЕРГИЮ`): строки `(Т1) день` и `(Т2) ночь` — из них берутся показания счётчика, «Расход в расчётном периоде (кВт∙ч)», тариф и сумма. В режиме «Объём» для таких услуг в таблице появляется колонка «Показания» (предыдущие → последние), а в подсказке на графике к объёму добавляются показания. Нулевые счета (0 руб., без расхода) просто не дают строк и не считаются ошибкой.

Остальные форматы пропускаются с предупреждением.

Сводные квитанции, в которых есть только итоговая сумма без расшифровки по услугам (например, «К оплате за месяц» в пустом бланке), учитываются как одна строка «ЖКУ (ИТОГ ПО КВИТАНЦИИ)». Если за тот же месяц есть детальная квитанция другого поставщика с той же суммой, сводная строка пропускается, чтобы не удваивать платёж.

Месяц берётся из текста платёжки (`за Август 2026`, `август 2026`), если не получилось — из имени файла. Если строки начислений не найдены, формат не распознан или месяц не определён, файл пропускается, а на странице появляется предупреждение.

## Ограничения

- Поддерживаются форматы ЕПД, квитанции УК и счёта Мосэнергосбыта. Незнакомые форматы пропускаются с предупреждением — их разбор можно добавить, если пришлёте образец.
- При изменении парсеров старая версия кэша в БД игнорируется автоматически: после обновления нажмите ⟳, чтобы PDF разобрались заново.
- Отчёт строится только по PDF, которые вы положили в папки; платёжки за месяцы вне выбранного периода не показываются.
- Веб-сервер по умолчанию слушает `0.0.0.0` (чтобы открывался из браузера Windows при запуске в WSL); в интернет порт не выставляйте — в нём ваши платёжки.
