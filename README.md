# mosobleirc-stats

Неофициальный Python-клиент личного кабинета [МосОблЕИРЦ](https://lkk.mosobleirc.ru): **начисления по месяцам с разбивкой по категориям** — в виде веб-страницы с графиком или таблицы/CSV/JSON в консоли.

Публичного API у МосОблЕИРЦ нет: скрипт использует те же запросы, что и веб-ЛКК, с вашими логином и паролем. Используйте только для личных нужд и с учётом пользовательского соглашения ЛКК.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка через env

Все параметры задаются переменными окружения. Можно положить их в `.env` рядом с проектом (он подхватится автоматически):

```bash
cp .env.example .env
```

```dotenv
MOSOBLEIRC_PHONE=+79001234567
MOSOBLEIRC_PASSWORD=пароль
```

Основные переменные:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `MOSOBLEIRC_PHONE` | — | телефон ЛКК |
| `MOSOBLEIRC_PASSWORD` | — | пароль ЛКК |
| `MOSOBLEIRC_TOKEN` | — | готовый `X-Auth-Tenant-Token` вместо логина |
| `MOSOBLEIRC_ACCOUNT` | все счета | фильтр: id/номер или часть названия ЛС, через запятую |
| `MOSOBLEIRC_MONTHS` | `12` | сколько месяцев собирать |
| `MOSOBLEIRC_END_MONTH` | предыдущий месяц | последний месяц отчёта, `YYYY-MM` |
| `MOSOBLEIRC_VALUE` | `charged` | показатель: `charged` (начислено, ₽) или `volume` (объём, ед.) |
| `MOSOBLEIRC_SHIFT` | `1` | сдвиг месяца запроса относительно месяца начисления |
| `MOSOBLEIRC_ANCHOR_DAY` | `15` | день месяца запроса |
| `MOSOBLEIRC_CACHE_DIR` | `data/raw` | кэш ответов ЛКК |
| `MOSOBLEIRC_TOKEN_FILE` | `~/.cache/mosobleirc/token.json` | файл кэша токена |
| `MOSOBLEIRC_HOST` | `0.0.0.0` | адрес веб-сервера |
| `MOSOBLEIRC_PORT` | `8765` | порт веб-сервера |

Если в аккаунте включён второй фактор (SMS/e-mail/приложение), клиент запросит код в консоли. ЛКК работает с 06:00 до 23:00 МСК; у входа есть лимит попыток — не запускайте вход с неверным паролем много раз.

## Веб-страница с графиком

```bash
python -m mosobleirc web
# в консоли появятся адреса, например:
#   http://localhost:8765/      — из браузера Windows
#   http://172.x.x.x:8765/      — IP WSL-машины, если localhost не открывается
```

Если страница не открывается из Windows: сервер слушает `0.0.0.0`, попробуйте `http://localhost:8765/`, затем IP из вывода команды (`ip -4 addr show eth0` в WSL). Порт занят — задайте `MOSOBLEIRC_PORT=8766`.

Сервер запускается один раз: при изменениях кода или `.env` он перезапускается автоматически (в течение секунды), вам достаточно обновить страницу в браузере. Отключить автоперезапуск: `MOSOBLEIRC_RELOAD=0`.

Страница показывает один блок «Начисления по услугам»:

- помесячный стек по категориям **из квитанций ЕПД (PDF)**: за каждый месяц скачивается платёжка и парсится таблица услуг; если квитанций нет, блок откатывается к текущему расчёту `charge-details`;
- диаграмма занимает всю ширину страницы, легенда — справа от неё одним столбцом; первый пункт легенды соответствует верхнему сегменту столбца, и в этом же порядке услуги идут в таблице под диаграммой, с разбивкой по разделам платёжки («Жилищные услуги», «Коммунальные услуги», «Иные услуги»; добровольное страхование входит в «Иные»). Клик по услуге включает/выключает её на графике, наведение — подсвечивает, кнопка «Скрыть все»/«Показать все» переключает все услуги сразу; у каждой услуги и группы в легенде есть иконка «?» с пояснением (например, что такое ОДН или ТКО); общая сумма над столбцом пересчитывается по видимым услугам;
- над каждым столбцом — итоговая сумма за месяц, при наведении — подсказка по конкретной услуге;
- клик по месяцу (по столбцу на графике или по месяцу в таблице) открывает квитанцию ЕПД за этот месяц в новой вкладке (`/api/receipt_pdf?month=YYYY-MM`).

Переключатели: лицевой счёт, период (6/12/24/36 месяцев), показатель («Начислено, ₽» / «Объём, ед.»). Кнопка «Обновить из ЛКК» перезапрашивает данные (обычная перезагрузка страницы читает кэш).

Кэши (поэтому переключение периода почти мгновенное):

- PDF квитанций — `data/receipts/{ЛС}/{месяц}.pdf`;
- распарсенные строки — `data/receipts/{ЛС}/{месяц}.json` (пересоздаётся, если PDF новее);
- агрегат по запросу (счета + месяцы + показатель) — в памяти сервера;
- ответы `/api/data` — в браузере, чтобы переключение туда-обратно не ходило на сервер.

Статус под заголовком честно показывает, что произошло: «скачано квитанций: N» (были запросы в ЛКК), «разобрано квитанций: N» (читались PDF), «из кэша» (ничего не запрашивалось).

Для разбора PDF нужен `pypdf` — он в `requirements.txt` (`pip install -r requirements.txt`).

## Консольные команды

```bash
python -m mosobleirc accounts            # список лицевых счетов
python -m mosobleirc turnover            # начислено/оплачено по месяцам (оборотная ведомость)
python -m mosobleirc months              # таблица: категории × месяцы (из квитанций ЕПД)
python -m mosobleirc months --format csv --out charges.csv
python -m mosobleirc months --format json
python -m mosobleirc collect             # только выгрузка в кэш
python -m mosobleirc probe --months 4    # диагностика: какие периоды отдаёт API
```

Параметры команд дублируют env (`--months`, `--value`, `--account`, `--shift`, …) и переопределяют их.

## Как читаются данные

**Команда `turnover`** использует оборотную ведомость:
`GET /api/api/clients/personal-accounts/{ЛС}/turnover-statements?year=&page=&size=&debtType=UTILITIES`
— по каждой строке `accrualsAmount` (начислено), `paidAmount` (оплачено), `balanceStart`/`balanceEnd` (остаток на начало/конец периода). Если ведомости нет, команда сообщает об этом (начисления смотрите через `months`).

**Разбивка по услугам** — из квитанций ЕПД:
`GET /api/api/personal_account/receipts_by_period/{ЛС}?date=YYYY-MM-01&serviceType=UTILITIES`
возвращает PDF единого платёжного документа за месяц. Из таблицы «Расчёт размера платы» берутся только два показателя:

- **объём услуг** (в единице измерения услуги) — `--value volume`;
- **«Начислено по тарифу»** (деньги) — `--value charged` (по умолчанию).

Колонки «Перерасчёты», «Задолженность/Переплата», «Оплачено» и «ИТОГО» игнорируются, строки с нулевым начислением не попадают в отчёт. PDF кэшируются в `data/receipts/{ЛС}/{месяц}.pdf`, результат разбора — в соседний `{месяц}.json`.

Если квитанций нет, используется текущий расчёт
`GET /api/api/personal_account/charge-details/{ЛС}?date=YYYY-MM-DD` (услуга `nm_service`, объём `vl_charged_volume`, начислено `sm_charged`), результат кэшируется в `data/raw/{ЛС}/{дата}.json`.

## Калибровка `--shift`

Относится к запасному источнику `charge-details` (когда квитанций нет): API отдаёт не произвольный месяц, а последнее сформированное начисление на указанную дату, поэтому в ЛКК при запросе «на сегодня» отображается расчёт за прошлый месяц. По умолчанию для месяца `M` запрос уходит с датой 15-го числа месяца `M+1` (`MOSOBLEIRC_SHIFT=1`). Если сервис вернёт не те месяцы, выполните:

```bash
python -m mosobleirc probe --months 4
```

и посмотрите колонку «Периоды в ответе» — при необходимости поменяйте `MOSOBLEIRC_SHIFT`/`MOSOBLEIRC_ANCHOR_DAY`. Если в ответе есть явное поле периода (`dt_period`, `period`, …), оно используется автоматически и сдвиг не важен.

## Ограничения

- API неофициальный и может измениться в любой момент (эндпоинты разобраны из фронтенда `lkk.mosobleirc.ru`).
- Двойной `/api/api/...` в запросах данных — не баг: так роутится сайт.
- Веб-сервер по умолчанию слушает `0.0.0.0` (чтобы открывался из браузера Windows при запуске в WSL); в интернет порт не выставляйте — в нём ваши квитанции и ЛС.
- Данные выгружаются только по ЛС, видимым вашей учётной записи.
